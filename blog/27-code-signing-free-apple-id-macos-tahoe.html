Testing iOS Code Signing in Jenkins Without Paying Apple — Free Personal Teams Still Work on macOS Tahoe

No Apple Developer Program membership, no $99. You can still sign real on-device iOS builds through a free Apple ID “Personal Team” and run them from a Jenkins pipeline. This post covers how to sign up, the limitations, and — importantly — what actually changed on macOS Tahoe (26) and newer that can break your CI signing scripts.

1What you get for free, and what you don’t

A plain Apple ID gives you a free Apple developer account. No payment, no enrollment form. When you sign into that account in Xcode (Settings → Accounts), Xcode creates a Personal Team for you and can sign builds with “Automatically manage signing” selected. That covers development builds you install on your own devices.

What the free team can doWhat it cannot do
Sign and run iOS development builds on your own deviceSubmit to the App Store or TestFlight
Generate an iOS Development certificate + provisioning profile automaticallyCreate distribution certificates / App Store profiles
Test the whole signing path inside a Jenkins pipelineUse capabilities that require a paid membership
Build for the simulator (no signing needed at all)Exceed ~3 apps registered to the free Apple ID
⚠
The 7-day expiry is the catch. Free-team certificates and provisioning profiles expire after 7 days. In CI you handle it by re-running the automatic-signing profile generation on every build — Xcode creates a fresh profile each time, so Jenkins builds keep working as long as the Apple ID is signed in on the build Mac.
✓
Two zero-account escape hatches. If you only need to prove the pipeline works: build for the simulator (no signing required) or disable signing for device builds with CODE_SIGNING_ALLOWED=NO CODE_SIGNING_REQUIRED=NO. Both need no Apple ID at all.

2How to sign up (official links)

  1. Create the free Apple ID: https://appleid.apple.com
  2. Log into the Apple Developer site with it (no payment step needed): https://developer.apple.com/account
  3. Open Xcode → Settings → Accounts, add that Apple ID, and your Personal Team appears automatically.
  4. In the target’s Signing & Capabilities tab, tick “Automatically manage signing” and select your Personal Team.

3Does it still hold on macOS Tahoe (26) and newer?

Yes. Free Personal Team signing is not deprecated and nothing in the macOS 26 / Xcode 26 releases removes it. Apple’s own forums still show free accounts signing builds on Sequoia 15.7+ and Tahoe, and Xcode 26 officially runs on macOS Sequoia 15.6 – Tahoe 26.x. But several security-related changes since Xcode 16 do affect CI scripts that sign automatically — get these right and your pipeline survives upgrades:

ChangeWhat it isWhat to do in Jenkins
Provisioning profile location moved (Xcode 16+)New profiles are stored at ~/Library/Developer/Xcode/UserData/Provisioning Profiles, not the old ~/Library/MobileDevice/Provisioning ProfilesUpdate any script that greps or reads the old path; Xcode still loads old profiles, but new downloads land in the new folder
WWDR intermediate cert rotationApple rotated the Worldwide Developer Relations certificate and the App Store receipt signing cert (Jan 2025)Let Xcode manage certs; if your pipeline uses security/manual keychain tricks, make sure the current AppleWWDRCA is in the build machine’s keychain or verification fails
Stricter codesign“resource fork, Finder information, or similar detritus not allowed” is now a hard errorKeep CI build outputs clean — no .DS_Store, no xattrs left by unzip/scp, before the sign step runs
macOS-level signing rulesOn Apple silicon all executables must be signed; ad-hoc signing covers local tools and is unaffectedNothing to change — iOS app signing via Xcode automatic signing is a separate path from macOS Gatekeeper/notarization rules
Tahoe is the last Intel macOSRosetta 2 support ends with macOS 27; Tahoe gets security-only support in 2026Prefer an Apple-silicon build agent if you are choosing CI hardware now
ⓘ
Best-practice CI shape. Install Xcode on the Jenkins Mac, sign into the free Apple ID once in Xcode (this stores credentials), and let automatic signing create/refresh the profile on each build. That is the whole trick — the free team’s 7-day profile expiry becomes a non-issue because every build generates a new profile.

5The bottom line

  • It works. Free Personal Team signing is alive on macOS Tahoe and newer — no paid account needed to exercise the real signing path in Jenkins.
  • Watch the moving parts. The profile-folder move, the WWDR rotation, and the stricter codesign are the three things that quietly break old CI signing scripts after a macOS/Xcode upgrade.
  • Embrace automatic signing. On a free team, let Xcode regenerate the profile on every build; never hand-craft profiles in CI.
  • Remember the limits. No App Store/TestFlight, ~3 apps, 7-day profiles — fine for testing pipelines, not for shipping.
