Every Signal, One Map: Telemetry and Test Tooling in Tables

This stack generates a lot of artifacts — 34 metric families on the proxy alone, another 40-odd on four exporters, spans, log streams, feedback scores, and alerts. And it is tested with four different rigs. This post is the reference map: what is generated, where each thing goes, and how the load and unit tests run. Each section is a tab.

Exporters 5 (Prometheus) OTLP pushes 3 Opik scores 3 + 3 judge Alerts 41 Test rigs 4 + 40 unit tests

1Metrics: five Prometheus exporters, scraped not pushed

Every mlx_* metric is served as a Prometheus text endpoint and scraped by VictoriaMetrics every 10 s — nothing is pushed over OTLP. That split was an explicit audit decision (post 4): the OTLP metrics path was removed from the proxy so each series exists exactly once.

5Load tests: four rigs, all against the proxy

Every bench tool targets the proxy (127.0.0.1:8080/v1/chat/completions), streams by default, uses temperature: 0.0, and sends X-Mlx-Trace: 1 so every request lands in Opik. Concurrency is thread-based (stdlib urllib + thread pools), never async.

RigMeasuresHow it runsOutput
tools/bench.pyStreaming TTFT, generation time, tok/s per requestPrompt matrix (short/medium/long) or one fixed-concurrency burst; --iters, --concurrencytable + optional --json
tools/bench_load.py main rigTTFT/latency/tps p50-95-99, throughput tok/s, error rate--sweep ramps concurrency 1→2→4→8→16; --sustain N soaks while snapshotting :9102/:9104/:9105 every interval; --profile stream on/off × prompt size. --duration/--settle control each levelJSON report → tools/bench-reports/{label}-{ts}.json
tools/bench_agentic.pyTurns, per-turn TTFT, wall time, tool-call validity, completion-in-budgetScenarios calculator/tri_tool/planner against a deterministic stub tool registry; streaming chat with tools; full transcript re-sent each turn; --runs × --agents concurrent loopsJSON report → tools/bench-reports/
tools/smoke.pyRing init + all_sum correctness across ranksRuns mlx.core on the cluster nodes directly (not HTTP); --backend ringconsole

How a load run actually works

  • Each concurrency level spawns N worker threads that loop run_one() until a stop event fires after --duration seconds.
  • Each run_one returns per-request ttft, total, gen_time, comp_tokens, tps, ok/error — aggregated into percentiles and error rate.
  • Results are correlated against VM-scraped cluster metrics (GPU mem, KV util, supervisor state) snapshotted during --sustain.
  • No RPS controller — workers fire as fast as they can; there is no rate limiter or think time (documented gap, ghz/k6/locust are drop-in options).

6Unit & integration tests: 40, in the repo venv

Run with .venv/bin/python -m pytest tests/ -q (Python 3.14 venv at repo root; both modules import mlx_metrics_proxy directly, no network needed for the confidence tests).

FileTestsWhat it proves
tests/test_confidence.py30 pure unitperplexity, renormalised top-k entropy (lower-bound), top-2 margin, confidence_stats, score_confidence incl. malformed-input tolerance, strip_logprobs/choice_logprobs, SSE-frame synthesis round-trips (content, tool calls, identity fields), _conf_metadata
tests/test_proxy_rewrite.py10 e2eagainst a StubUpstream that mirrors mlx_lm.server (logprobs on non-streaming only, SSE + [DONE] + connection-close framing, optional tool calls, configurable error status). The proxy runs in-process on an ephemeral port; real HTTP drives it. Verifies: logprobs injected upstream but stripped for the client with matching Content-Length, client-requested logprobs pass through, injection disable, tool calls survive the strip, upstream 503 passthrough, streaming untouched when sampling off, de-streamed requests still parse as SSE, de-streamed tool calls reach the client, and de-streamed requests record no TTFT. Metrics are read back from the in-process proxy’s /metrics.
ⓘThe bench tools themselves are not unit-tested — only the proxy’s confidence/rewrite layer is. The stub upstream is the trick that makes the whole injection/de-streaming path testable without a GPU.
