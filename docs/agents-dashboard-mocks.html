Open problems

Node uptime — lowest 8

The restart counter is the tell that a plain up/down view misses: an agent that crashes and is restarted by launchd every 40 seconds reads as "up" on every scrape.

None of these can be built today

I checked the live endpoints before drawing these. The metric contract does not currently support a fleet view — five gaps, all of which the Go binary should fix by construction.

1. Five different liveness metric names

mlx_up, mlx_hw_up, mlx_kv_agent_up, mlx_server_up, mlx_log_tailer_up. With five agents you can write five queries. With 100 you cannot — the grid above needs one series, mlx_agent_up{role,node}, or every panel becomes a hand-maintained union.

2. Only one agent self-reports its node

mlx_hw_up carries node="rank0". The other four carry no node label at all — it is injected by the VictoriaMetrics scrape config. That works for two hand-written targets and collapses at twenty. The agent must label itself.

3. Model path does not exist anywhere

model="mlx-community/Qwen3.5-4B-MLX-8bit" is a Hugging Face repo id, not a location on disk. Nothing emits where the weights actually live. Mock B's last column is currently unfillable.

4. No version or build info

No agent reports its own version. "Is node-14 running the old binary?" has no answer today — and it is the first question you ask when one node behaves differently.

5. Uptime is partial

mlx_hw_uptime_seconds (node) and mlx_server_uptime_seconds exist. The proxy, kv and log agents report no uptime, so "restarted 40 seconds ago" is invisible for three of five roles.

The contract these mocks assume

Two series carry every panel above. Everything else is a join onto them.

# one liveness series for every agent, whatever its role
mlx_agent_up{role="proxy", node="rank0", instance="192.168.1.64:8080"} 1

# one info series carrying the text: model identity, location, build
mlx_agent_info{
  role="supervisor", node="rank0",
  version="1.4.0", commit="a7aeb08",
  model="mlx-community/Qwen3.5-4B-MLX-8bit",
  model_path="/Users/dk/.cache/huggingface/hub/models--mlx-community--Qwen3.5-4B-MLX-8bit"
} 1

# plus, per agent, uniformly:
mlx_agent_uptime_seconds{role, node}
mlx_agent_restarts_total{role, node}

Why info-metric, not labels on everything

Putting model_path on every counter multiplies cardinality across hundreds of series. One _info gauge at value 1, joined with * on(instance) group_left(model_path), keeps it to one series per agent.

Why role as a label, not a name

Roles change — a merged kv+log agent becomes one role. A label absorbs that; five metric names require editing every dashboard and alert.

Down vs no-data

These mocks separate them. Push-based delivery makes the distinction sharper: absent_over_time means "nothing arrived", which is not the same as an agent reporting itself unhealthy.

Restart counter is load-bearing

With KeepAlive in the plist, a crash-looping agent looks up on most scrapes. Without mlx_agent_restarts_total the fleet view lies.
